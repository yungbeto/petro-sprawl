# Working notes for Claude Code

The app is Petro Sprawl (renamed from Energy terminal on 2026-11-01). The repository, folder, Vercel project and production URL keep the old `energy-terminal` name.

Read `SPEC.md` fully before starting any work. `docs/product-brief.md` explains the why.

## How to work here

- Build milestone by milestone (SPEC section 11). Stop for review at the end of each milestone.
- Never fabricate statuses, capacities, flows or URLs. If something can't be sourced, use `unknown` and add it to `TODO-research.md`.
- Keep transforms pure and tested; keep thresholds and constants in `src/lib/config.ts`.
- Ask before adding dependencies beyond the stack in SPEC section 8.
- World Monitor is a reference only (AGPL-3.0). Don't copy its code or data files.
- Writing style for UI copy and docs: sentence case, no uppercase eyebrow labels, no em dashes.

Hosting is Vercel (`vercel.json`): a static Vite build of `dist/`, plus link previews. `middleware.ts` sends `/` with a `view` or `sel` to the page function (`server/page.ts`), which swaps the tags between the `share:start` and `share:end` markers in `index.html` for the page's; The image function (`server/og.tsx`) draws its card image. Home keeps the static `public/og.png`. Deployment Protection is off (turned off 2026-11-01 so the data providers asked for permission can see the app), so every URL, previews included, is public. Production is https://petrosprawl.fyi (bought 2026-11-01; DNS on Cloudflare). https://energy-terminal-omega.vercel.app still serves the same deployment, and stays: it's the link sent to UN Comtrade and JODI. With the GitHub repo connected, every push to main deploys, including the data commits. `.vercelignore` keeps raw data, saved articles and secrets out of CLI uploads.

Scheduled jobs run every 6 hours in `.github/workflows/data.yml` and commit `public/data` when it changes. The claims refresh runs weekly in `.github/workflows/claims.yml`: confirmations go to main, other drafts go to its one rolling pull request, `claims/review` (the repository must allow GitHub Actions to create pull requests). The news scan runs every 3 hours in `.github/workflows/news.yml` the same way; `NEWS_SCAN=off` as a repository variable turns it off. Every job writes through `publishDataset` in `jobs/lib/output.ts`: new data must pass its zod schema or the previous file stays and the failure is recorded in `meta/<id>.json`.

## Gotchas

- Playwright runs Chromium on the GPU on macOS (`playwright.config.ts`). Software WebGL draws the pipeline layer at about 1 fps, so camera animations never settle and URL tests time out. CI without a GPU needs another plan.
- The dev server exposes the map as `window.__etMap` so the smoke test can click real features. Dev only.
- Pipelines and LNG terminals are built in two steps: `import:gem` / `import:lng` (raw GEM to `data/derived/`), then `build:curated` (curated records win). Edit `data/curated/pipelines-evidence.json` or `data/curated/lng-evidence.json`, never the files in `public/data/`.
- Owner and parent links come from GEM's ownership tracker, matched by name: GEM's entity ID lists aren't in the same order as the names (a row pairs "Exxon Mobil Corp" with TC Energy's ID), and the oil tracker lists owner IDs only. `companyHomePage` (`jobs/lib/gem.ts`) tries the row's IDs, then a name only one company has.
- Oil terminals are curated only (`data/curated/oil-terminals.json`). Their locations come from PortWatch's ports database or a GEM pipeline end, never from memory; mark a point that's near but not at the terminal with `pointApprox`. Disruptions at a terminal use `assetKind: 'terminal'` and show on the pipelines that end there.
- Measured flow evidence is derived in the browser (`withMeasuredEvidence`, and `withMeasuredLngEvidence` for ALSI send-out), not stored in `pipelines.json` or `lng-terminals.json`. So are Home's measured changes (`src/lib/measuredChanges.ts`, thresholds in `MEASURED_CHANGES`).
- Home's "Latest updates" cards (up to `HOME_HERO.cards`) are the disruptions in effect with the newest source `publishedAt` (`lastReported`), not the newest start. Adding a source to an old disruption moves its card to the front.
- PortWatch fails queries at random. `fetch:portwatch` fetches each chokepoint and port on its own (`eachWithFallback` in `jobs/lib/output.ts`), tries failures once more, then keeps that one's previous series. The run still counts as failed (`lastAttempt.ok: false`, red in Actions) so it's visible. It also stops starting requests after `PORTWATCH.budgetMinutes` (the `deadline` option of `fetchJson`), so it publishes what it has before the workflow step's 20-minute cap kills it; raise the cap and the budget together.
- ALSI now and then answers a facility with an empty page; `fetch:alsi` asks again before reporting it as having no data.
- MapLibre 6 loads its worker from a separate file. `src/map/MapView.tsx` imports it with `?url` and calls `setWorkerUrl`; without that, tiles never load in dev or in the build.
- The claims refresh never trusts what the model says about a page: `verifyDraft` (`jobs/lib/claims.ts`) fetches it and checks the quote and the metadata date. Haiku has invented dates from "days ago" labels; the date check caught it. Keep the checks in code, not in the prompt.
- "Where is my fuel from?" (M7): EIA's refinery and blender net production of gasoline counts blending of components shipped in, so it is never "made in the region". That share is what the region used minus receipts and imports. The region view's fuel is `fuel=` in the URL, left out for gasoline.
- EIA's import totals by PADD can hold more than the countries it names (Gulf Coast gasoline blending components, 2026-08: 834 total, 765 named). The rest is kept as one `EIA.unnamedPartner` row and always folds into "other countries"; countries adding up to more than the total still fail the fetch.
- "Where is my oil from?" (M6) shares are of crude flowing into a PADD (imports, receipts from other PADDs, field production), not of refinery input; the residual method went negative for the Midwest. A ZIP code or city never goes in the URL, only `region/padd-n`.
- News scan (M9): Google News links are Google redirects that can't be read, so Google News only ranks stories; the article comes from a GDELT link or a search of the publisher's site. GDELT answers 429 at its documented 5-second pace (`NEWS.gdeltGapMs` is 8 s) and reports errors as plain text with status 200. Anthropic's web search rejects a whole request when an allowed domain blocks its crawler (reuters.com does); `scan-news.ts` drops those and retries. Names that are also common words or tickers go in `NEWS.weakTerms` (Druzhba is a football club too).
- A source marked `unreviewed: true` was committed by the news scan without a person checking it, and the page says so; since 2026-11-03 that includes the first source of a new disruption (`disruptionReview` in `jobs/lib/news.ts`), and since 2026-11-05 a new source from any domain on a disruption in effect. Claims (`Evidence`) carry the same field since 2026-11-05: a confirmation the claims refresh committed from a domain off the trusted list. Delete the field to mark it reviewed. What still needs a person: status changes, first claims, ended disruptions, changes of cause, and new disruptions that don't meet `disruptionReview`.
- Review pull requests roll: `news/review` and `claims/review` are rebuilt from main on every run (force-pushed), keeping the drafts waiting in the branch's drafts file and adding new ones. Edits on those branches other than deleting a draft from that file are replaced on the next run.
- Headline thumbnails are drawn in the browser from our own geometry and `countries.json` (`src/lib/thumbnail.ts`), never from the article's image: press photos aren't ours to reuse. Publisher icons are saved by the scan and served from this site, raster only (an SVG on our own origin could run script), so a reader's browser never calls a publisher.
- Gas storage takes one source per country, in the order of `STORAGE_SOURCES` (`countryStorage` in `src/lib/gasStorage.ts`): AGSI+, then EIA for the US and Statistics Canada for Canada, then JODI. Only AGSI+ gives a fill, so the list and the map compare each country with itself a year earlier (percent of gas held). JODI values it doesn't assess (code 3) are dropped: Russia's read 50 million m³. JODI's Canada figure runs a month behind Statistics Canada's. JODI's CSV link sits behind a script; the job reads the file list from `api.publisher.jodidata.org`. Statistics Canada's old storage table (25-10-0057-01) stopped at 2025-12; the job reads 25-10-0086-01.
- JODI and UN Comtrade were asked in writing (2026-11-01) whether their data can be published here. If either answers with conditions or a takedown, comply: drop the source's fetch and its rows. Comtrade answered 2026-11-02 by pointing to its re-dissemination rules (https://uncomtrade.org/docs/re-dissemination-of-data/), which cover this use: shares are derived metrics, and the per-partner values in `crude-imports.json` (337 rows) are a free extraction well under its 100,000-record limit. That holds only while the site stays free and non-commercial (no ads, sponsorship or paid features) and the Comtrade rows stay under 100,000; otherwise write to comtrade@un.org first. Credit it as "Source: UN Comtrade."
- Oil origins (`FEATURES.fuelOrigins`, `view=origins`) and gas storage (`FEATURES.gasStorage`) can be switched off. `viewEnabled` and `selectionEnabled` (`src/lib/views.ts`) gate the rail, search, links, the layer list and Home's figure; their smoke tests skip while off, and the fetches still run.
- A country is one page (`sel=country/<iso2>`, `CountryDetail`) holding its gas storage and its crude imports; old `storage/<iso2>` links still open it. The map layer is still called `storage`: `countryMode` (`'imports'` on oil origins) switches it between the storage scale and the importers' neutral fill.
- Crude imports (`jobs/lib/crudeImports.ts`): Eurostat writes Greece as EL and the UK as UK (mapped in `EUROSTAT_OIL.iso2`); Comtrade's world rows often have no net weight, so importers are ranked by value; only rows with customs code C00, mode 0 and second partner 0 are totals. Comtrade is reused while its records' `retrieved` date is under `COMTRADE.refreshDays` old; the meta `fetchedAt` changes every run, so don't use it for that.
- The phone tab bar holds `PHONE_TABS.slots`; with more sections on, the last slot is More (`phoneTabs` in `src/lib/views.ts`, `MoreTab` in `App.tsx`).
- A surface draws only its own map layers (`VIEW_LAYERS`) plus the open item's (`visibleLayers`); the layer list is Home's alone. A new surface needs an entry in `VIEW_LAYERS`.
- Link previews read `dist/share/`, built from `public/data/` by every `npm run build`, so a card always matches its deploy's data; no function calls a live source. The functions fetch `index.html` and the index from their own deployment. A card states only figures its page shows, with the source. `@vercel/og` 1.0.x throws "Dynamic require of fs" under plain Node ESM, so it stays on 0.11. The functions' code is in `server/`; `npm run build` bundles it into `api/_dist/` (`vite.functions.config.ts`, gitignored), and `api/og.ts` and `api/page.ts` only re-export those bundles. Vercel transpiles `api/` file by file and keeps extensionless imports, which Node's ES module loader can't resolve (the first preview deploy failed that way), so don't put code there. To try the functions locally, run `npx vite preview` and call their `GET` with a Request for that origin.
- "What changed since last visit" is off (`FEATURES.visitChanges` in `src/lib/config.ts`); its smoke test skips while it is. When on, it lives in `localStorage` under `et.visits` (`src/lib/summary.ts`). To see changes locally, edit the stored `current` snapshot (older `savedAt`, a different status) and reload; the smoke test does the same.
